## High

1. **Caller cancellation stops working mid-stream when `headerTimeoutMs` is set** — `src/harness/llm/openai.ts:403`. The `finally` on the fetch removes the `forwardAbort` listener and clears the timer as soon as headers arrive, so `attemptController` is never aborted again; the body reader (`openai.ts:434`) is bound to the per-attempt signal, not the caller's. A turn can no longer be stopped once the stream starts. *Fix: keep forwarding in an outer `finally` that runs after streaming, or race the reader against `signal`.*
2. **New default `maxStepsPerTurn: 48` silently truncates legitimate long turns and misfiles them** — `src/harness/limits.ts:116`, `src/harness/agent/agent.ts:513`. A turn past the ceiling closes as `limit`; `run()` then sets `stopped` (`agent.ts:316`), so queued user input is stranded, and `src/web/server.ts:4452` records automations as `failed: run ended: limit`. *Fix: raise/opt-in the default and treat `limit` as a soft stop (advance the queue, don't report a failure).*

## Medium

3. **Most new provider options are never wired by the host** — `src/web/server.ts:933-940`, `src/bins/headless.ts:319-327`. `supportsPromptCacheKey`, `supportsStore`, `maxTokensField`, `headerTimeoutMs`, `wire`, and `providerOptions` are only ever set in tests, so those code paths are dead in production. *Fix: source them from `ProviderConfig` or delete the unused options.*
