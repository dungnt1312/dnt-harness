# Git Panel v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Zed's branch picker, per-hunk stage/unstage/restore, AI commit message, conflict resolution and a more usable panel layout (split diff, row actions + context menu, compact commit area, tree view) to the workbench Git panel.

**Architecture:** Server work lives in focused modules beside `src/web/project-git-ops.ts` (branches, hunks, conflicts, commit message) and plugs into the existing per-repository queue and the `POST …/git/:op` NDJSON route. The web panel is split into a list pane and a diff pane; pure rules (tree building, branch ordering, fuzzy match, commit suggestion) live in model files with unit tests; components consume them.

**Tech Stack:** Node.js 24, TypeScript, system git CLI, HTTP NDJSON, React 19, Radix Popover/Dialog, Tailwind, Vitest (node + jsdom).

**Spec:** `docs/superpowers/specs/2026-10-13-git-panel-v2-design.md` (read it first; it carries the Zed citations).

## Global Constraints

- Port Zed behaviour and copy (`/tmp/zed-src`, `zed-industries/zed@c66312b`); do not invent alternatives. Merge/rebase Abort/Continue is **not** built (Zed has none).
- Every git invocation goes through `runGitCommand`/`runGitQuery` (`src/web/project-git.ts`) so trust flags and the login-shell environment apply. No new git npm dependency, no `git apply`.
- Every mutation runs inside `runProjectGitOperation` (queue + fresh status in `done.status`). Read-only queries may run outside the queue.
- Client paths pass `contain()` and follow `--`. Client ref names never start with `-`, are checked with `check-ref-format` and, where they must exist, `show-ref --verify`.
- New routes reuse the existing browser-principal, archived-workspace, CSRF and `400 before stream` rules of `handleProjectGitAction`.
- Untrusted mode keeps the v1 flag set; hooks do not run for checkout/switch when untrusted (they are disabled by `core.hooksPath=/dev/null`).
- Existing behaviour stays: `pathFilter` turn view (commit area hidden), `focusPath` from chat cards, askpass, toasts with View Log, Restricted Mode banner.
- Hover-revealed controls take no layout space (memory: hover-actions-no-layout-cost); touch (`pointer:coarse`) shows them always.
- Markdown stays under `docs/` or `plans/`. Use pnpm. Per task: run the affected spec files; at the end `pnpm test`, `pnpm run typecheck`, `pnpm run build:web`.

## Review Focus

1. A file edited in the terminal between showing the diff and clicking a hunk button must be refused with `The file changed since the diff was shown. Refresh and try again.`, never stage the wrong lines — Task 2 pins it.
2. A hunk operation on a CRLF file or one without a final newline must keep line endings and the missing newline byte-for-byte — Task 2 pins it.
3. A branch name typed with spaces or starting with `-` must not reach git as an option; `create-branch` with `-f` is a 400 — Task 1 pins it.
4. A commit-message request whose client disconnects must abort the model stream (no leaked request) — Task 4 pins it with a fake provider observing `signal.aborted`.
5. Selecting another file while a diff for the previous one is still loading must never show the old file's diff under the new header — Task 6 pins it (generation guard).

  const exists = async (ctx: Context, ref: string) => (await git(ctx, ['show-ref', '--verify', '--quiet', ref])).ok
  export async function switchBranch(ctx: Context, name: string): Promise<Step> {
    if (name.startsWith('-')) throw new ProjectGitError(`Branch '${name}' not found`)
    if (await exists(ctx, `refs/heads/${name}`)) return git(ctx, ['checkout', name])
    if (await exists(ctx, `refs/remotes/${name}`)) {
      const slash = name.indexOf('/'); const remote = name.slice(0, slash); const branch = name.slice(slash + 1)
      const link = (await exists(ctx, `refs/heads/${branch}`))
        ? ['branch', '--set-upstream-to', `${remote}/${branch}`, branch]
        : ['branch', '--track', branch, `${remote}/${branch}`]
      return sequence(() => git(ctx, link), () => git(ctx, ['checkout', branch]))
    }
    throw new ProjectGitError(`Branch '${name}' not found`)
  }
  export async function createBranch(ctx: Context, name: string, base?: string): Promise<Step> {
    const checked = await checkedBranch(ctx, name)   // throws "'<n>' is not a valid branch name"

      if (base.startsWith('-') || !((await exists(ctx, `refs/heads/${base}`)) || (await exists(ctx, `refs/remotes/${base}`)))) {
        throw new ProjectGitError(`'${base}' is not a branch`)
      }
      return git(ctx, ['switch', '-c', checked, base])
    }
    return git(ctx, ['switch', '-c', checked])
  }
  export async function deleteBranch(ctx: Context, name: string, remote: boolean, force: boolean): Promise<Step> {
    if (name === '' || name.startsWith('-') || !(await exists(ctx, `${remote ? 'refs/remotes/' : 'refs/heads/'}${name}`))) {
      throw new ProjectGitError(`Branch '${name}' not found`)

  ```ts
  export type GitHunkStatus = 'staged' | 'unstaged' | 'partial'
  export interface GitHunkRef { readonly oldStart: number; readonly oldLines: number; readonly newStart: number; readonly newLines: number; readonly fingerprint: string }
  export interface GitHunk extends GitHunkRef { readonly status: GitHunkStatus }
  export interface RawHunk { readonly oldStart: number; readonly oldLines: number; readonly newStart: number; readonly newLines: number; readonly lines: readonly string[] } // lines keep their marker
  export function parseHunks(unifiedDiff: string): RawHunk[]                            // pure

  export async function stageHunk(ctx: Context, rel: string, hunk: GitHunkRef): Promise<Step>

  export async function restoreHunk(ctx: Context, rel: string, hunk: GitHunkRef): Promise<Step>
  ```
  `GitDiffReport.hunks: readonly GitHunk[]` (always present, maybe empty).
  `GitOperationRequest` gains `{ type: 'stage-hunk' | 'unstage-hunk' | 'restore-hunk'; path: string; hunk: GitHunkRef }`.
  `GitCommandOptions.stdin?: 'pipe' | 'ignore' | Buffer` — a Buffer is written to the child's stdin and then closed.

**Algorithm (spec §2):**
1. Offered only if `hasHead`, the path is tracked in HEAD (`git cat-file -e HEAD:<rel>` ok), status entry not conflicted, worktree file exists or is deleted, and the reading diff is not binary.
2. Display hunks D = `parseHunks(gitDiff text)` (the same `--unified=3 HEAD` diff `gitDiff` prints; reuse its text before `parseDiff`).
3. W = `parseHunks(git diff -U0 --no-color -- <rel>)` (index↔worktree), S = `parseHunks(git diff -U0 --no-color --cached HEAD -- <rel>)` (HEAD↔index).
4. `overlaps(start, count, s, e)`: count > 0 → `start < e && s < start+count`; count == 0 → `s <= start + 1 && start + 1 <= e` … with `[s, e)` itself possibly empty (`count==0` for the other side means point `s+1`). Implement one helper `rangeOf(start, count) = count === 0 ? [start + 1, start + 1] : [start, start + count]` treated as closed-open with empty ranges matching when `a0 <= b1 && b0 <= a1` for empty ones and `a0 < b1 && b0 < a1` otherwise. Unit-test it directly.
5. status: `stagedPart = S.some(s => overlap(D.old, s.old))`, `unstagedPart = W.some(w => overlap(D.new, w.new))`; `!unstagedPart → 'staged'`, `!stagedPart → 'unstaged'`, else `'partial'`.
6. **stage-hunk**: index text I = `git show :<rel>` (Buffer; missing → refuse "not in the index"); worktree text T. For each W hunk overlapping D.new, in **descending** `oldStart` order (so earlier offsets stay valid): `I = replaceLines(I, w.oldStart, w.oldLines, linesOf(T, w.newStart, w.newLines))`. Then index write.
7. **unstage-hunk**: H = `git show HEAD:<rel>`. For each S hunk overlapping D.old, descending: `I = replaceLines(I, s.newStart, s.newLines, linesOf(H, s.oldStart, s.oldLines))`. Then index write.
8. **restore-hunk**: refuse for created files. T' = T with D's new range replaced by D's old lines taken from H (`linesOf(H, D.oldStart, D.oldLines)`); write with `fs.writeFile` keeping mode (`fs.stat` before, `chmod` not needed since writeFile preserves an existing file's mode).
9. Index write (Zed `set_index_text`): `git hash-object -w --stdin --path <rel>` with stdin = new I → sha; mode = `(stat.mode & 0o111) ? '100755' : '100644'` from the worktree file (deleted → read the mode from `git ls-files -s -- <rel>`); `git update-index --add --cacheinfo <mode>,<sha>,<rel>`. On failure return `{ ok: false, stderr: 'Failed to stage:\n' + stderr }`.
10. Stale check before any write: recompute D for the path and require one hunk with equal `oldStart, oldLines, newStart, newLines, fingerprint`; else `throw new ProjectGitError('The file changed since the diff was shown. Refresh and try again.')`.
11. `linesOf(buf, start, count)`: split the Buffer after each `\n` (last piece may lack `\n`), return pieces `[start-1, start-1+count)`. `replaceLines` joins pieces; when the replaced region was the last piece without `\n` and new lines end with `\n`, that is correct by construction (bytes copied from the other side). Pure byte work: no UTF-8 decode, so CRLF and missing final newline survive.
